# 评论系统升级方案（对齐主流博客）

> 背景：CMS 演示模板的 Comments 目前是通用内容类型（name/e-mail/comment/article 字段），无用户绑定、无审批机制、无专用端点。目标：**登录用户可评论、文章可设置"评论需审批后显示"**，行为对齐主流博客系统。
> 约束：开发阶段、从 0 开始、破坏性覆盖、不写兼容老数据代码。

## 1. 现状

| 项 | 现状 |
|---|---|
| 评论数据 | `comments` collection，字段：name / e-mail / comment / article(relation) |
| 评论者身份 | 无用户绑定（访客自填名字邮箱）；评论内容 `created_by` 未使用 |
| 审批机制 | 无。无"待审/已批准"概念 |
| 公开 API | 通用内容端点；`publishedContentQuery` **只返回 `published_at` 非空**的内容（可复用为"审批可见"过滤） |
| 前台 | 本仓库自带 Vue SPA（`resources/js/frontend/`），同域调用 `/api/project/...`；**无登录 UI、无认证** |
| 认证体系 | 平台用户 web session（admin 后台）；公开 API 写操作用 sanctum 项目 token；前台无用户登录 |
| 权限 | 已完成：Spatie RBAC（super_admin/user）+ `project_user(role)` + ProjectPolicy；`manageContent` = owner/admin/editor |

## 2. 主流做法对照（以 WordPress 为基准）

| 维度 | WordPress | 本方案 |
|---|---|---|
| 评论者身份 | 访客可填名评论 / 登录用户 | **仅登录用户**（用户明确要求），作者名=登录用户名 |
| 全局默认审批 | Settings→Discussion："Comment must be manually approved"（默认关） | 项目/模板提供默认值（默认 `auto` 直接显示，可切换） |
| 文章级覆盖 | 单篇文章可开启/关闭评论 | **文章级 `comments_moderation` 字段：auto / approval / disabled** |
| 状态机 | Pending / Approved / Spam / Trash | **待审(=未发布) / 已批准(=已发布) / 已删除(软删)**，复用现有发布机制 |
| 免审规则 | "曾有评论被批准的作者自动通过" | P2 可选（同一用户历史评论已批准→新评论自动显示） |
| 审核操作 | 后台列表按状态筛、批准/垃圾/删除 | admin 后台**评论审核视图**：按文章分组、批准/拒绝/删除 |

## 3. 推荐方案（复用现有架构，零表结构迁移）

核心思想：**评论仍然是 `comments` collection 的内容**；"审批"复用内容发布机制（`published_at`），"评论者"复用 `created_by` + 自动填充字段（延续 Author 改造模式）。

### 3.1 数据与字段

- **Articles collection 新增字段** `comments_moderation`（enumeration 类型）：
  - `auto`（默认）→ 评论提交后立即显示
  - `approval` → 评论进入待审，管理员批准后才显示
  - `disabled` → 文章关闭评论（提交被拒，提示已关闭）
- **Comments collection 字段调整**：
  - `name` / `e-mail`：改为**后端自动填充**（= 登录用户姓名 / 邮箱），前端不再手动输入；`required` 改为 false（自动填充在表单校验之后注入，required=true 会先失败）
  - `comment`：保留（评论正文，required=true）
  - `article`：保留（relation 到 articles）
- **评论状态 = 发布状态**（零迁移）：
  - 已批准 = `published_at` 非空（公开 API 自动可见）
  - 待审 = `published_at` 为 null（公开 API 不可见）
  - 删除 = 软删除（SoftDeletes 已启用）
- **评论者**：`created_by` = 当前登录用户 id；`name` 字段自动填用户名（序列化不变，前台直接显示）

### 3.2 公开 API（博客前台调用）

| 端点 | 方法 | 认证 | 行为 |
|---|---|---|---|
| `/api/project/{id}/articles/{article_id}/comments` | GET | 公开 | 返回该文章**已批准**评论列表（复用 relation + published 过滤） |
| `/api/project/{id}/comments` | POST | **登录用户** | 提交评论；校验文章存在、评论未关闭；按文章设置写 `published_at`；自动填 name/e-mail/created_by |
| `/api/auth/me` | GET | 登录用户 | 返回当前用户（前台显示登录态/退出） |

认证说明：前台与后台同域，评论提交走 **web session**（`auth:web`，同源 cookie），无需新登录页——用户用现有 `/login`、`/register` 页面登录后即可评论。外部前端项目接入可后续扩展 sanctum 用户 token（P2）。

### 3.3 admin 后台审核

| 端点（admin-api） | 方法 | 权限 | 行为 |
|---|---|---|---|
| `/admin-api/content/comments/{project_id}` | GET | manageContent | 评论列表：待审 / 全部（按文章分组，显示评论者、时间） |
| `/admin-api/content/comments/approve/{content_id}` | POST | manageContent | 批准：置 `published_at=now` → 前台可见 |
| `/admin-api/content/comments/reject/{content_id}` | POST | manageContent | 拒绝：软删除（评论者不可见，可从回收站恢复/删除） |

前端：admin SPA 新增"评论审核"入口（项目侧边栏），待审列表 + 一键批准/拒绝，与现有内容列表（可手动编辑/发布评论）互补。

### 3.4 前台博客（frontend SPA）

- 文章详情页新增**评论区块**：
  - 评论列表（已批准，按时间正序，显示作者名/时间/内容）
  - 提交框：已登录 → 显示用户名 + 评论输入框 + 提交；未登录 → 显示"登录后评论"链接
  - 文章 `comments_moderation=disabled` → 不显示评论区块
  - `approval` 模式提交后提示"评论已提交，审核通过后显示"

### 3.5 权限

- 评论（任何登录用户）与内容管理（owner/admin/editor）解耦：评论提交用 `auth:web`（登录即可）
- 审批/删除评论 = `manageContent`（owner/admin/editor），与内容管理一致
- 超管全放行（现有 Gate::before 已覆盖）

## 4. 关键决策点

1. **默认审批模式**：推荐默认 `auto`（对齐 WordPress 默认"直接显示"），管理员可逐篇开启 `approval`；若更重视防垃圾评论可改默认 `approval`（一处配置）
2. **访客评论**：用户明确"用户登录后可以评论"，不做访客匿名评论
3. **评论者展示**：直接展示登录用户名（实时），不存快照——用户改名后评论显示新名（与作者字段行为一致）
4. **嵌套/回复评论**：本期不做（主流博客基础版为平铺列表），P2 可加 `parent` 字段实现楼层回复

## 5. 实施步骤

- **P1（核心，本期）**
  1. 模板：Articles 加 `comments_moderation` 字段；Comments 的 name/e-mail required=false + 注释
  2. Seeder：评论数据补 `created_by`（演示用户）；播种 2-3 条待审评论（published:false）演示审批；更新演示文章模式字段（一篇 approval、一篇 disabled）
  3. 后端：公开 API 评论控制器（列表/提交，`auth:web` + 项目校验）；`/api/auth/me`；admin 审核控制器 + 路由（approve/reject/list，manageContent）
  4. 前端 admin：评论审核视图（待审列表 + 批准/拒绝）
  5. 前端 blog：文章详情评论区块（列表 + 提交 + 登录提示 + 审批提示）
  6. 测试：提交（auto 立即可见 / approval 待审 / disabled 拒绝）、审核权限、公开 API 只暴露已批准、未登录 401
- **P2（可选后续）**：历史已批准用户免审；嵌套回复；评论通知；sanctum 用户 token 支持外部前端

## 8. 状态机升级（2026-09-15，对齐主流博客四态）

- **评论状态**：新增 `status` 枚举字段（pending / approved / spam / trash，对齐 WordPress `comment_approved` 四态），替代"published_at 表示已批准、软删表示移除"的隐式机制，成为评论唯一状态源：
  - 提交：auto→`approved`、approval→`pending`、disabled→422
  - 公开 API 只返回 `approved`
  - 审核：approve→approved、reject→trash、spam→spam、restore→trash/spam→pending、delete→物理删除（forceDelete）
- **管理端内容列表**：评论集合显示四态 tab（All/Approved/Pending/Spam/Trash）与对应徽标，不再显示 published/draft；批量操作同步为 approve / mark as spam / move to trash / restore / delete（`POST /admin-api/content/comments/bulk/{project_id}`）
- **审核页**：Pending/Approved/Spam/Trash/All 五视图 + 计数；单条操作 Approve/Spam/Trash/Restore/Delete
- **测试**：新增 5 个用例（状态过滤+计数、spam/restore 循环、批量四操作+删除、admin 列表状态过滤、viewer 全端点 403），更新全部 published_at 断言为 status；全套 **251 passed（720 assertions）**，npm build 通过
- **开发期坑**：counts 曾复用带 published_at 条件的 clone 查询导致 approved=0，改为独立查询；Content 模型默认序列化不含 meta，status 便捷属性在 admin index 循环中注入

P2（未做）：历史已批准用户免审、嵌套回复、评论通知、sanctum 用户 token 支持外部前端。
